# Telegram 群视频自动下载器设计规格

## 1. 目标

在当前 Windows 电脑上运行一个轻量、可长期持续运行的 Telegram 个人账号下载器。用户通过图形配置器从账号已加入的群组中明确选择一个或多个目标群；后台服务只扫描和监听这些群，首次启用某个群时回溯其全部历史消息，并在发现符合条件的新视频后优先自动下载。

项目产生的依赖、会话、配置、状态库、缓存、临时文件、日志和下载文件必须保存在 `D:\Codex Project\Telegram自动化脚本` 内，不主动向 C 盘写入项目数据。

## 2. 已确认范围

- 使用 Telegram 个人账号登录，首次登录需要手机号、验证码；账号开启二步验证时还需要二步验证密码。
- 支持同时选择一个或多个群组。
- 只处理用户明确选入白名单的群组；白名单为空时拒绝启动，绝不自动下载账号下全部群。
- 首次启用群组时回溯全部历史消息，完成后持续监听新消息。
- 下载 Telegram 普通视频，以及 MIME 类型为 `video/*` 的文件。
- 排除 GIF、带动画属性的媒体、圆形视频消息以及非视频媒体。
- 使用轻量图形界面完成账号登录、群组选择、运行控制和状态查看；图形界面关闭后，后台下载器继续运行。
- 单下载工作进程，实时视频优先，历史视频在后台逐步补齐。
- 电脑保持开机和联网时持续运行；不承诺跨关机运行。

## 3. 不在本期范围

- 不绕过 Telegram 权限、群访问限制或账号风控。
- 不下载未被白名单选中的群、私聊或其他会话。
- 不下载图片、音频、语音、GIF、圆形视频或普通文档。
- 不删除 Telegram 原消息，也不自动删除已下载文件。
- 不提供远程网页管理、云端控制、托盘常驻界面或多账号并行。
- 不创建 Windows 计划任务或启动项，因为这些会在 Windows 系统位置保存元数据，与严格的 C 盘约束冲突。
- 不对单个未完成文件做字节级续传；进程中断后，该文件从头重新下载。任务级进度、历史扫描进度和已完成文件会断点恢复。

## 4. 技术方案

### 4.1 技术栈

- Python 3.11 或更高版本。
- Telethon 稳定版，用于 MTProto 个人账号登录、历史消息遍历、新消息事件和媒体下载。
- Tkinter/ttk，用于仅在配置和查看状态时运行的 Windows 图形界面。
- Python 标准库 `sqlite3`，用于持久化群组扫描游标、下载任务和运行状态。
- Python 标准库 `tomllib`，用于读取配置；写入由项目内的小型配置序列化函数负责。
- PowerShell 守护脚本，用于设置项目内环境目录、启动后台进程及异常退出后重启。

### 4.2 采用 Telethon 的原因

Telethon 直接支持异步事件、历史消息遍历、媒体下载和自动重连，单个 Python 进程即可完成本项目。定时轮询会增加延迟和重复 API 请求；TDLib 虽然可靠，但原生依赖、构建和本地数据库更重，不符合轻量目标。Pyrogram 官方仓库已经归档并停止维护，因此不采用。

## 5. 项目目录与磁盘约束

```text
Telegram自动化脚本/
├─ .venv/                         项目虚拟环境
├─ .cache/                        pip 与应用缓存
├─ .tmp/                          下载临时文件
├─ .runtime/
│  ├─ credentials.toml            API ID、API Hash、手机号
│  ├─ telegram.session            Telethon 登录会话
│  ├─ state.sqlite3               SQLite 状态库
│  ├─ downloader.pid              后台进程标识
│  ├─ supervisor.pid              守护进程标识
│  ├─ heartbeat.json              图形界面读取的运行快照
│  └─ stop.flag                   用户主动停止标记
├─ config.toml                    群组白名单与非敏感运行设置
├─ downloads/
│  └─ 群名称_群ID/
│     └─ 年-月/
│        └─ 消息ID_原文件名.扩展名
├─ logs/                          轮转日志
├─ src/                           应用代码
├─ tests/                         自动化测试
└─ docs/                          设计和实施文档
```

所有启动脚本在启动 Python 或 pip 前设置以下环境变量到项目内绝对路径：

- `TEMP`、`TMP` 指向 `.tmp`。
- `PIP_CACHE_DIR` 指向 `.cache\pip`。
- `PYTHONPYCACHEPREFIX` 指向 `.cache\pycache`。
- 虚拟环境固定为项目内 `.venv`。

下载目录不允许配置为项目目录之外的路径。现有 Python 解释器本身可能安装在其他磁盘，但本项目不在其安装目录创建依赖或项目数据。

## 6. 图形配置器

图形配置器使用 Tkinter/ttk，按需启动，不作为常驻进程。界面分为三个区域。

### 6.1 账号

- 输入并本地保存 Telegram API ID、API Hash 和手机号。
- API Hash 使用密码框显示。
- 验证码和二步验证密码只用于当前登录流程，不写入配置或日志。
- 登录成功后将授权状态保存到项目内 `telegram.session`。
- 会话失效时显示“需要重新登录”，不在后台无限提交认证请求。

### 6.2 群组选择

- 登录后读取账号当前可访问的群组列表，不显示私聊。
- 表格显示复选框、群名和群 ID，并提供群名搜索。
- 用户可以选择一个或多个群；界面持续显示已选择数量。
- 保存时把稳定群 ID 和当时的群名原子写入 `config.toml`。
- 配置器不提供“默认全选”；白名单为空时提示并拒绝启动下载器。
- 后台服务每 5 秒检查配置文件修改时间。新增群会建立扫描状态并开始全量回溯；移除群会停止接收和扫描该群，但保留状态与已有文件，以便以后重新启用后继续。

### 6.3 运行控制与状态

- “启动下载器”按钮启动隐藏的 PowerShell 守护进程；重复点击不会创建第二个实例。
- “停止下载器”按钮写入 `stop.flag`，后台服务完成当前数据库事务后退出，守护进程识别为用户主动停止且不再重启。
- 显示后台状态、最后心跳时间、当前下载文件、实时等待数、历史等待数、成功数、失败待重试数以及每个群的历史扫描进度。
- 提供“打开下载目录”和“打开日志目录”按钮。
- 图形界面退出不影响后台服务。

## 7. 后台组件边界

### 7.1 配置组件

负责读取、校验和原子保存配置。API 凭据与非敏感群组白名单分开保存。后台配置热更新只接受完整且校验成功的新配置；读取到写入中的文件或非法配置时继续使用上一份有效配置并记录错误。

### 7.2 Telegram 网关

封装 Telethon 客户端，负责登录会话、群实体解析、历史消息遍历、新消息事件、消息重新获取和媒体下载。其他组件不直接依赖 Telethon 的具体对象，以便使用替身进行测试。

### 7.3 媒体分类器

输入一个规范化消息对象，输出“可下载视频”或“忽略”。判定规则如下：

- 普通视频可下载。
- 文档 MIME 类型以 `video/` 开头时可下载。
- 存在动画/GIF 属性时忽略。
- 视频属性标记为圆形消息时忽略。
- 无媒体、图片、音频、语音和其他文件忽略。

### 7.4 扫描协调器

每个启用群维护两个游标：

- `latest_seen_id`：已经观察到的最新消息 ID，用于服务停机后的新消息补抓。
- `history_cursor_id`：历史扫描已经到达的最旧消息 ID，用于继续向更早消息回溯。

启动时先注册新消息事件，再执行停机期间补抓，最后继续历史扫描。新群先记录当前最新消息边界，然后从最新向最旧扫描全部历史。扫描每处理一批消息就提交游标，不因进程中断而从头重扫。

### 7.5 持久任务队列

SQLite 本身作为持久任务队列，唯一键为 `(chat_id, message_id)`。任务状态为：

- `pending`：等待下载。
- `downloading`：当前正在下载。
- `retry_wait`：失败后等待下一次重试。
- `completed`：文件已经完整落盘。
- `permanent_error`：消息或群已永久不可访问，需要用户处理。

实时和停机补抓任务优先级高于历史任务。单个大历史视频开始后不强制中断，但当前文件完成后下一任务优先选择实时视频。内存中只保存固定容量的唤醒通知，不保存完整历史任务列表，因此历史量很大时内存仍有上限。

### 7.6 下载工作器

默认只运行一个下载工作器：

1. 从 SQLite 原子领取最高优先级任务。
2. 重新获取消息，确保文件引用有效。
3. 检查目标路径和磁盘可用空间。
4. 流式下载到 `.tmp` 下与任务唯一对应的临时文件。
5. 校验已知文件大小；成功后原子移动到最终路径。
6. 提交 `completed` 状态和最终文件信息。

服务启动时把遗留的 `downloading` 状态恢复为 `pending`，清理对应残缺临时文件并从头重新下载。若最终文件存在且大小与 Telegram 元数据一致，则直接修复数据库状态为 `completed`；文件缺失或大小不符则重新下载。

## 8. 文件路径规则

- 群目录使用经过 Windows 文件名清理的群名，并追加稳定群 ID，避免重名和改名冲突。
- 月目录按消息时间转换为 `Asia/Shanghai` 后使用 `YYYY-MM`。
- 文件名格式为 `消息ID_原文件名.扩展名`。
- 原消息没有文件名时使用 `消息ID_video.扩展名`。
- 清理 Windows 禁止字符、保留名称、尾随空格和尾随句点，并限制文件名长度，为目录和扩展名预留路径长度。
- 相同群内消息 ID 保证唯一，因此相同原文件名不会覆盖。

## 9. 运行流程

1. 用户双击图形配置器。
2. 用户填写 API 凭据并完成首次登录。
3. 配置器加载群组列表，用户勾选目标群并保存。
4. 用户点击启动；守护脚本设置项目内环境目录并启动后台服务。
5. 后台服务校验会话和非空白名单，注册新消息处理器。
6. 对每个群补抓 `latest_seen_id` 之后的消息。
7. 对尚未完成历史扫描的群继续从 `history_cursor_id` 向旧消息扫描。
8. 可下载视频以幂等方式写入 SQLite；下载工作器优先处理实时任务。
9. 服务持续等待 Telegram 更新，同时推进历史扫描和失败重试。
10. 图形配置器通过只读心跳快照与 SQLite 汇总显示状态。

## 10. 异常恢复

### 10.1 网络和 Telegram 限流

- Telethon 自动重连失败时使用指数退避，延迟从 5 秒增加到最多 5 分钟，并加入少量随机抖动。
- Telegram 返回 FloodWait 时按服务器指定秒数等待，不进行紧密重试。
- 文件下载出现临时网络错误时进行 5 次快速重试；仍失败则进入 `retry_wait`，15 分钟后再次尝试，任务不会丢失。

### 10.2 权限和认证

- 单个群不可访问时将该群标记为需要处理，暂停该群扫描，其他群继续运行。
- 单条消息被删除或永久不可访问时标记 `permanent_error`，不阻塞队列。
- 会话失效时停止 Telegram 请求，在心跳状态和图形界面显示“需要重新登录”。

### 10.3 磁盘

- 下载前要求可用空间至少为已知文件大小加 512 MiB；文件大小未知时至少保留 512 MiB。
- 空间不足或目录不可写时暂停领取新任务，每 60 秒重新检查，并在状态和日志中报告。
- 程序不自动删除已有文件、临时文件以外的内容或日志保留范围之外的数据。

### 10.4 进程

- PowerShell 守护进程在后台服务意外退出后重启，间隔从 5 秒增加到最多 5 分钟。
- 用户主动停止通过 `stop.flag` 区分，守护进程不重启。
- 后台服务持有单实例锁，避免两个下载器同时写入同一状态库和文件。
- Windows 运行期间调用执行状态 API 阻止系统因空闲自动休眠；不阻止用户主动睡眠、关机或重启。
- 因不创建系统启动项，电脑重启后用户需要再次打开配置器并点击启动。

## 11. 日志、状态与隐私

- 日志写入 `logs/downloader.log`，单文件 10 MiB，最多保留 5 个备份。
- 日志记录时间、级别、组件、群 ID、消息 ID、目标路径和错误摘要。
- 日志不记录验证码、二步验证密码、API Hash 或完整会话内容；手机号只允许掩码显示。
- 心跳每 5 秒原子更新到 `.runtime/heartbeat.json`，包含进程状态、当前任务、队列计数、累计计数、群扫描游标和最近错误摘要。
- `.runtime`、`downloads`、`logs`、`.tmp`、`.cache`、`.venv` 和本地配置加入 `.gitignore`，防止凭据与下载内容被提交。
- 账号会话文件具有登录权限，只有可信的 Windows 用户才能访问项目目录。

## 12. 测试策略

### 12.1 单元测试

- 配置读取、校验、原子写入和非法配置回退。
- 非空白名单要求、群新增与移除差异计算。
- 普通视频、视频文件、GIF、圆形视频和非视频媒体分类。
- Windows 文件名清理、重名避免、月份目录和路径长度限制。
- SQLite 状态转换、唯一键去重、实时优先和遗留 `downloading` 恢复。
- 重试时间、FloodWait、磁盘阈值和日志脱敏。

### 12.2 集成测试

- 使用伪 Telegram 网关模拟历史消息与实时消息同时到达，验证实时任务优先。
- 模拟服务在扫描中和下载中退出，验证游标继续、残缺文件清理及已完成文件不重复下载。
- 模拟配置热更新，验证只启动新增群、立即忽略移除群且保留已有状态。
- 模拟网络中断、文件引用失效、群权限丢失、磁盘不足和会话失效。
- 使用临时项目根目录验证所有可配置写入都位于项目根目录内。
- 对图形界面的控制器和后台调用边界做自动化测试，视觉布局做 Windows 手工检查。

### 12.3 真实联调

- 用户在图形界面亲自输入验证码和可选二步验证密码。
- 先选择一个可控测试群，验证历史视频下载、新视频实时下载、停止和重启恢复。
- 再选择多个群，验证严格白名单和配置热更新。
- 运行故障注入与持续运行冒烟测试，记录空闲和下载时资源占用。

## 13. 验收标准

- 白名单为空时不能启动；存在白名单时只访问和下载所选群。
- 新增群会从全部历史开始补齐；已完成任务在重启后不重复下载。
- 服务停机期间产生的新视频在再次启动后能够补抓。
- 新视频在当前文件结束后优先于剩余历史视频下载。
- GIF、圆形视频和非视频媒体不会进入下载队列。
- 下载中断不会留下被误认为成功的最终文件。
- 网络、限流、单群权限和单文件错误不会导致其他群永久停止。
- 图形界面关闭后后台服务继续运行，并能重新打开查看状态和停止。
- 使用项目启动脚本安装和运行时，项目依赖、缓存、临时文件、会话、状态、日志和输出均位于 `D:\Codex Project\Telegram自动化脚本`。
- 后台没有忙轮询，队列和下载采用流式处理；图形界面关闭且同步空闲时，以 Windows 实测工作集不高于 150 MiB 为轻量验收目标。

## 14. 用户责任与限制

下载器只能访问登录账号本来有权读取的内容。用户应确保下载和保存群内视频符合群规则、内容权利和适用法律。Telegram 账号限制、群消息被删除、电脑断电、主动休眠、关机或网络长期不可用时，程序无法保证即时下载，但恢复后会依据持久游标补抓仍可访问的内容。
