# Telegram 视频自动下载器

这是一个面向 Windows 的轻量 Telegram 个人账号工具。它只监听你在图形界面中明确勾选的群组和已订阅频道。每个目标可以单独决定是否补抓历史视频；无论历史开关是否开启，程序都会持续监听新视频，并在电脑或网络恢复后补抓停机期间仍可访问的消息。

依赖、缓存、会话、数据库、日志和进程控制数据都保存在项目目录内，不写入用户启动目录，也不创建 Windows 计划任务。视频默认保存在项目 `downloads/`；你也可以在“运行”页明确选择其他可写的本地磁盘目录，只有视频成品和对应断点会进入该目录。

## 前提

- Windows 10 或 Windows 11。
- Python 3.11 或更高版本。
- Telegram 个人账号，并且该账号本来就有权读取目标群组或已订阅频道。
- 在 [Telegram API 开发工具](https://my.telegram.org) 获取个人账号使用的 API ID 和 API Hash。
- 下载和保存群组或频道内视频时，请遵守群组/频道规则、内容权利和适用法律。

## 首次使用

1. 双击项目根目录的 `打开配置器.cmd`。首次启动会在项目内创建 `.venv` 并安装依赖，可能需要几分钟。
2. 在“账号”页填写 API ID 和 API Hash，点击“扫码登录”。API ID 和 API Hash 仍是 Telegram 客户端连接所必需的。
3. 使用已经登录的 Telegram 客户端扫描界面内的二维码；二维码过期会在原位置自动刷新。账号启用了二步验证时，在扫码区输入密码。
4. 如果扫码不可用，展开“使用手机号验证码登录”，填写手机号并按验证码流程登录。
5. 打开“群组/频道”页，点击“刷新群组/频道”，使用搜索框查找，再分别设置“监听”和“历史”。工具不提供全选，也不会默认监听账号下所有对话；新选择或重新选择的目标默认只监听新内容，“历史”默认关闭。
6. 点击“保存选择”。至少要选择一个群组或频道，否则不能保存或启动。
7. 打开“运行”页；如需修改保存位置，可选择或输入本地磁盘文件夹并点击“保存位置”。然后点击“启动后台”。随后点击右上角“×”会把配置器隐藏到系统托盘，后台下载不会因此停止。

开启某个目标的“历史”后，程序会从已保存的历史游标继续向前扫描全部可访问历史；关闭时只暂停历史扫描和历史任务领取，队列与游标不会删除。实时消息和停机补抓始终保持启用，并优先于历史任务下载。升级前已经存在的目标在首次读取旧配置时默认保持历史开启。

## 日常使用

- 双击 `打开配置器.cmd` 可随时重新打开界面查看本地状态；已有配置器隐藏在托盘时，重复启动只会恢复原窗口，不会出现第二个窗口或托盘图标。
- 配置器启动时会自动检查并复用项目内已授权会话；只要账号没有主动退出、撤销授权或使会话失效，就不需要再次扫码。
- 点击配置器右上角“×”会隐藏窗口。双击托盘图标或右键选择“打开配置器”可以恢复窗口。
- 托盘图标悬停文字会显示当前文件、下载百分比和速度；没有正在下载的文件时显示等待数和完成数。绿色表示正常运行，黄色表示正在启动或心跳异常，红色表示配置、登录或后台错误，灰色表示后台已停止。
- 托盘右键菜单可启动或停止后台、打开当前下载目录、打开 `logs`、检查更新、恢复配置器，以及退出托盘。“退出托盘”只关闭配置器和图标，**不会停止后台下载**；要停止下载请使用“停止后台”。
- 修改目标后保存：新目标默认只监听新内容；历史开关可随时单独开启或暂停。暂停时当前已经开始的历史文件允许完成，后续历史任务留在队列中；重新开启后继续扫描和下载。
- 移除目标后不再扫描或接收新任务，数据库中的队列、游标和已经下载的文件仍会保留；以后重新选择时历史默认关闭。
- 重新启用以前监听过的群组或频道时，会立刻从已保存的最新消息位置补抓停用期间的新视频，不会重新下载已完成内容。
- 服务持续运行期间每 5 分钟对已启用目标执行一次增量补抓，用于弥补短时断网或事件漏收。
- “运行”页会显示当前文件、已下载/总字节、百分比、平均速度、是否断点续传，以及实时、可执行历史、已暂停历史、重试、完成和永久失败数量。“当前文件进度”只表示正在下载的单个文件；进度条复用现有的 2 秒心跳刷新，百分比暂不可用时显示“正在准备”或“等待任务”，不增加下载线程、动画计时器或额外轮询。
- 修改下载位置后，正在处理或已有断点的任务继续使用原目录；尚未开始的任务和后续新任务使用新目录。已完成文件不会自动迁移，目标盘暂时不可用时任务保留并重试，不会静默写回旧目录。
- “运行”页的“运行自检”会检查项目路径、Python、`cryptg` 加速依赖、托盘依赖与内存图标、内存二维码组件、登录任务是否清理、配置、凭据格式、当前下载目录与目标盘空间、在线更新本机组件、数据库、心跳与停止标记的一致性，以及 Telegram 群组/频道可见性，并显示报告位置。
- 点击“停止后台”会创建项目内停止标记，取消当前 Telegram 请求、保留安全断点并让服务有序退出。
- 再次启动会清除停止标记，恢复未完成队列、历史游标和可用的 `.part` 断点。

## 项目内文件位置

以下路径都相对于本项目根目录：

- `.runtime/credentials.toml`：API ID、API Hash，以及仅供备用验证码登录使用的可选手机号。
- `.runtime/telegram.session`：Telegram 登录会话，具有账号登录权限。
- `.runtime/state.sqlite3`：群组/频道扫描游标和持久下载队列；SQLite 的 WAL/SHM 文件也在此目录。
- `.runtime/heartbeat.json`：图形界面读取的后台状态。
- `.runtime/downloader.lock`、`.runtime/supervisor.pid`、`.runtime/stop.flag`：进程控制文件。
- `.runtime/gui.lock`、`.runtime/gui-activate.request`：配置器单实例锁和重复启动时的窗口唤醒请求，不含账号或下载内容。
- `.runtime/update-request.json`、`.runtime/update-result.json`：一次在线更新的固定字段请求和脱敏结果；完成结果在配置器显示后删除。
- `downloads/`：默认下载根目录，最终视频按“群组或频道 / 月份”保存。
- `<选择的下载目录>/.tg-video-downloader/partial/`：选择外部保存位置后，该目标盘上的隐藏断点目录；工具不会枚举或删除同目录中的其他用户文件。
- `logs/downloader.log`：轮转日志，单文件最多 10 MiB，保留 5 个备份。
- `logs/update.log`：手动在线更新的阶段日志，不记录凭据、Telegram 内容或下载文件名。
- `logs/diagnostics/doctor-<UTC时间>.json`：每次自检生成的脱敏 JSON 报告。
- `.tmp/`：Python 临时数据和一次性更新器副本；旧版本遗留的合法 `.part` 会安全迁移到任务绑定的目标盘。
- `.cache/`：pip 缓存和 Python 字节码缓存。
- `.venv/`：项目专用 Python 虚拟环境和依赖，包括 Telethon 使用的 `cryptg` 本地加速。

建议把项目放在空间充足的 D 盘或其他非系统盘。不要移动 `.runtime`、`.tmp`、`.cache`、`logs` 或 `.venv` 等控制目录；视频保存位置可以在界面中改为任意可写的本地固定盘或可移动盘目录，不支持 UNC 网络共享。

## 在线更新

在线更新只在你点击“检查更新”时联网，优先读取 GitHub，连接失败时改用魔塔。程序只接受 `vX.Y.Z` 稳定标签；安装前会拒绝非 `master`、本地改动、未跟踪文件、登录任务未结束或非快进版本。文件搜索仅用于查看改动，安装始终是完整版本，不能选择部分程序文件。

如果后台原本在运行，更新器会正常停止它，成功或安全回滚后再恢复；原本停止则保持停止。更新器在 GUI 退出后从项目 `.tmp` 中的独立副本运行，更新依赖并验证导入；失败时只在工作区仍符合预期的情况下回滚本次版本文件。配置、Telegram 会话、SQLite、断点、已下载视频和用户选择的外部目录不进入版本恢复范围，阶段日志位于 `logs/update.log`。

`v0.1.0` 还没有内置更新器，需要按原方式手动拉取或覆盖到 `v0.2.0`，并在项目根目录运行一次 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1` 后再打开配置器；从 `v0.2.0` 开始，后续稳定版本可在工具内手动检查并一键更新。没有启动检查、定时检查或后台更新进程。

## 下载范围

会下载：

- Telegram 普通视频。
- MIME 类型为 `video/*` 的普通文件。

不会下载：

- GIF 或动画文档。
- 圆形视频消息。
- 图片、音频、PDF 和其他非视频文件。
- 未在图形界面中勾选的群组或频道内容。

下载器只有一个文件工作器。当前文件完成后，实时和停机补抓视频会排在历史视频之前。

## 恢复语义

- 已完成任务记录在 SQLite 中，不会因程序重启而重复下载。
- 每个群组或频道的最新消息游标和历史扫描游标都会持久保存。
- 异常退出时，处于下载中的任务会回到等待队列，合法的 `.part` 文件继续保留在任务已经绑定的下载盘。
- 下载固定使用 512 KiB 块。已对齐的 `.part` 会从现有字节偏移续传；未对齐文件先截断到上一个完整块，超过预期大小的文件才会删除并从 0 开始。
- 网络错误、停滞或后台停止会尽量保留完整块；连续 120 秒没有收到新字节时，当前 Telegram 请求会被取消并进入现有重试机制。
- 最终文件与 `.part` 位于同一个任务绑定卷；校验大小后在该卷内原子改名，避免跨盘复制，半成品不会冒充完成文件。

## 24 小时运行限制

- 电脑必须保持开机并联网；关机、重启或主动休眠时无法下载。
- 后台运行时会请求 Windows 阻止“空闲导致的系统休眠”，但不会阻止用户主动休眠、注销或关机。
- 电脑重启后需要手动双击配置器并点击“启动后台”。本项目不会创建系统启动项或计划任务，以免在 C 盘用户配置中产生数据。
- Telegram 删除消息、撤销群权限或长期不可访问后，程序无法保证补回对应内容。
- 开始或续传前会在任务绑定的目标盘要求可用空间至少为“尚未下载的剩余字节 + 512 MiB 安全余量”；空间不足时任务暂停等待，已有断点不删除。

## 故障处理

### 显示“需要重新登录”

在“账号”页优先重新扫码登录，然后点击“启动后台”。如果扫码不可用，可以展开手机号备用区重新发送验证码。二维码令牌、验证码和两种登录方式的二步验证密码都不会保存。

### 某个群组或频道显示访问错误

确认当前 Telegram 账号仍在群内或仍订阅该频道，并且可以读取消息。单个目标无权限不会终止其他目标的历史扫描；失败后会按 1 分钟、5 分钟、30 分钟的间隔重试，后续持续使用 30 分钟间隔，成功访问后自动清除错误和退避状态。

### 磁盘空间不足

释放当前任务绑定下载盘的空间；如果选择了可移动盘，也请确认盘符和目录仍可用。队列会保留并在重试时间到达后继续，不需要删除数据库，也不会自动回退到其他目录。

### 下载长时间没有变化

运行页和托盘每 2 秒从项目内心跳读取字节、百分比和速度。单次 Telegram 请求连续 120 秒没有新字节时会自动取消并重试，合法 `.part` 会在下一次请求中续传；无需手动删除临时文件。

### 后台没有运行

灰色托盘图标表示后台已停止，可右键选择“启动后台”。如果通知区域没有图标，重新双击 `打开配置器.cmd`；如仍失败，先在“运行”页点击“运行自检”，再查看 `logs/downloader.log`。

运行页常见状态：

- `running`：后台正常运行；同时显示当前文件、字节进度、百分比和平均速度。
- `stale`：后台最后报告为运行中，但心跳已超过 15 秒没有更新，通常表示进程卡住或已经退出。
- `needs_config`：配置、凭据格式或目标白名单无效，需要回到界面修正。
- `needs_login`：Telegram 会话失效，需要重新登录。
- `error`：后台发生未处理错误，可结合“最近错误”、日志和自检报告排查。
- “永久失败”：消息已删除或不可访问，不会无限重试；它只影响对应任务。
- “历史已暂停”：目标关闭历史后保留但暂不领取的历史任务数，不影响实时监听。

也可以在项目根目录直接运行命令行自检：

```powershell
.\.venv\Scripts\python.exe -m tg_video_downloader doctor
```

退出码 `0` 表示全部通过，`1` 表示存在警告，`2` 表示至少一项失败。每项检查相互隔离；完整报告会原子写入项目内 `logs/diagnostics/`，不会上传，也不会在报告中保留 API Hash 或手机号明文。

## 隐私与安全

- 二维码令牌只存在于内存和 Tkinter Canvas 中，不创建二维码图片或临时文件；过期、取消、成功或关闭窗口后会清空。
- 二维码令牌、验证码和两种登录方式的二步验证密码只在当前登录调用中使用，不写入配置、数据库、心跳、自检报告或日志。
- 已授权的项目内会话会在后续启动时自动复用；退出账号会使该会话失效。
- 日志会脱敏 API Hash 和手机号。
- 自检报告同样脱敏，且只保存在项目内 `logs/diagnostics/`。
- `.runtime/telegram.session` 等同于登录权限；不要分享 `.runtime`、不要提交到版本库，也不要放到不可信的同步盘。
- `config.toml` 只保存非敏感运行设置、下载根目录和明确选择的群组/频道；敏感 API 凭据单独位于 `.runtime`。

## 验证

在项目根目录打开 PowerShell，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1
```

该命令使用项目内 Python 执行完整测试和语法编译，并检查运行目录没有越出项目根。测试和编译产生的临时数据仍写入项目内 `.tmp` 与 `.cache`。
