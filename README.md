# Telegram 视频自动下载器

这是一个面向 Windows 的轻量 Telegram 个人账号工具。它只监听你在图形界面中明确勾选的群组：首次启用群组时回溯全部可访问历史视频，之后持续监听新视频，并在电脑或网络恢复后补抓停机期间仍可访问的消息。

所有由本项目主动产生的依赖、缓存、临时文件、会话、数据库、日志和下载内容都保存在项目目录内，不写入用户启动目录，也不创建 Windows 计划任务。

## 前提

- Windows 10 或 Windows 11。
- Python 3.11 或更高版本。
- Telegram 个人账号，并且该账号本来就有权读取目标群组。
- 在 [Telegram API 开发工具](https://my.telegram.org) 获取个人账号使用的 API ID 和 API Hash。
- 下载和保存群内视频时，请遵守群规则、内容权利和适用法律。

## 首次使用

1. 双击项目根目录的 `打开配置器.cmd`。首次启动会在项目内创建 `.venv` 并安装依赖，可能需要几分钟。
2. 在“账号”页填写 API ID、API Hash 和手机号，点击“发送验证码”。
3. 填写 Telegram 收到的验证码，点击“完成登录”。账号启用了二步验证时，再填写二步验证密码并再次完成登录。
4. 打开“群组”页，点击“刷新群列表”，使用搜索框查找群组，并逐个勾选需要下载的群。工具不提供全选，也不会默认监听账号下所有群。
5. 点击“保存选择”。至少要选择一个群，否则不能保存或启动。
6. 打开“运行”页，点击“启动后台”。图形界面可以随后关闭，后台下载不会因此停止。

首次启用一个群时，程序会从最新消息开始向前扫描全部可访问历史；实时消息和停机补抓任务会优先于历史任务下载。

## 日常使用

- 双击 `打开配置器.cmd` 可随时重新打开界面查看本地状态。
- 关闭配置器只关闭界面，不停止后台下载器。
- 修改白名单后保存：新增群开始历史扫描；移除群不再扫描或接收新任务，已经下载的文件会保留。
- 重新启用以前监听过的群时，会立刻从已保存的最新消息位置补抓停用期间的新视频，不会重新下载已完成内容。
- 服务持续运行期间每 5 分钟对已启用群执行一次增量补抓，用于弥补短时断网或事件漏收。
- “运行”页的“运行自检”会检查项目路径、Python、依赖、配置、凭据格式、磁盘、数据库、心跳及 Telegram 群可见性，并显示报告位置。
- 点击“停止后台”会创建项目内停止标记并让服务有序退出。
- 再次启动会清除停止标记，恢复未完成队列和历史游标。

## 项目内文件位置

以下路径都相对于本项目根目录：

- `.runtime/credentials.toml`：API ID、API Hash 和手机号。
- `.runtime/telegram.session`：Telegram 登录会话，具有账号登录权限。
- `.runtime/state.sqlite3`：群组扫描游标和持久下载队列；SQLite 的 WAL/SHM 文件也在此目录。
- `.runtime/heartbeat.json`：图形界面读取的后台状态。
- `.runtime/downloader.lock`、`.runtime/supervisor.pid`、`.runtime/stop.flag`：进程控制文件。
- `downloads/`：按“群组 / 月份”保存的最终视频。
- `logs/downloader.log`：轮转日志，单文件最多 10 MiB，保留 5 个备份。
- `logs/diagnostics/doctor-<UTC时间>.json`：每次自检生成的脱敏 JSON 报告。
- `.tmp/`：当前任务的 `.part` 临时文件和 Python 临时数据。
- `.cache/`：pip 缓存和 Python 字节码缓存。
- `.venv/`：项目专用 Python 虚拟环境和依赖。

请把整个项目放在空间充足的 D 盘或其他非系统盘。不要把上述运行目录改到项目之外。

## 下载范围

会下载：

- Telegram 普通视频。
- MIME 类型为 `video/*` 的普通文件。

不会下载：

- GIF 或动画文档。
- 圆形视频消息。
- 图片、音频、PDF 和其他非视频文件。
- 未在图形界面中勾选的群组内容。

下载器只有一个文件工作器。当前文件完成后，实时和停机补抓视频会排在历史视频之前。

## 恢复语义

- 已完成任务记录在 SQLite 中，不会因程序重启而重复下载。
- 每个群的最新消息游标和历史扫描游标都会持久保存。
- 异常退出时，处于下载中的任务会回到等待队列。
- 单个残缺 `.part` 文件不会从字节位置续传；该视频下次会从头下载。其他已完成文件和任务不受影响。
- 最终文件先在 `.tmp` 写入并校验大小，再原子移动到 `downloads`，半成品不会冒充完成文件。

## 24 小时运行限制

- 电脑必须保持开机并联网；关机、重启或主动休眠时无法下载。
- 后台运行时会请求 Windows 阻止“空闲导致的系统休眠”，但不会阻止用户主动休眠、注销或关机。
- 电脑重启后需要手动双击配置器并点击“启动后台”。本项目不会创建系统启动项或计划任务，以免在 C 盘用户配置中产生数据。
- Telegram 删除消息、撤销群权限或长期不可访问后，程序无法保证补回对应内容。
- 开始下载前要求可用空间至少为目标文件大小再加 512 MiB；空间不足时任务暂停等待。

## 故障处理

### 显示“需要重新登录”

在“账号”页重新发送验证码并完成登录，然后点击“启动后台”。验证码和二步验证密码不会保存。

### 某个群显示访问错误

确认当前 Telegram 账号仍在群内且可以读取消息。单个群无权限不会终止其他群的历史扫描；失败后会按 1 分钟、5 分钟、30 分钟的间隔重试，后续持续使用 30 分钟间隔，成功访问后自动清除错误和退避状态。

### 磁盘空间不足

释放项目所在磁盘的空间。队列会保留并在重试时间到达后继续，不需要删除数据库。

### 后台没有运行

重新打开配置器查看状态并点击“启动后台”。如仍失败，先在“运行”页点击“运行自检”，再查看 `logs/downloader.log`。

运行页常见状态：

- `running`：后台正常运行；同时显示当前下载文件名。
- `stale`：后台最后报告为运行中，但心跳已超过 15 秒没有更新，通常表示进程卡住或已经退出。
- `needs_config`：配置、凭据格式或群组白名单无效，需要回到界面修正。
- `needs_login`：Telegram 会话失效，需要重新登录。
- `error`：后台发生未处理错误，可结合“最近错误”、日志和自检报告排查。
- “永久失败”：消息已删除或不可访问，不会无限重试；它只影响对应任务。

也可以在项目根目录直接运行命令行自检：

```powershell
.\.venv\Scripts\python.exe -m tg_video_downloader doctor
```

退出码 `0` 表示全部通过，`1` 表示存在警告，`2` 表示至少一项失败。每项检查相互隔离；完整报告会原子写入项目内 `logs/diagnostics/`，不会上传，也不会在报告中保留 API Hash 或手机号明文。

## 隐私与安全

- 验证码和二步验证密码只在当前登录调用中使用，不写入配置、数据库、心跳或日志。
- 日志会脱敏 API Hash 和手机号。
- 自检报告同样脱敏，且只保存在项目内 `logs/diagnostics/`。
- `.runtime/telegram.session` 等同于登录权限；不要分享 `.runtime`、不要提交到版本库，也不要放到不可信的同步盘。
- `config.toml` 只保存非敏感运行设置和明确选择的群组；敏感 API 凭据单独位于 `.runtime`。

## 验证

在项目根目录打开 PowerShell，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1
```

该命令使用项目内 Python 执行完整测试和语法编译，并检查运行目录没有越出项目根。测试和编译产生的临时数据仍写入项目内 `.tmp` 与 `.cache`。
