# 可配置下载保存位置设计

## 背景与目标

当前下载器把所有最终视频固定保存到项目根目录的 `downloads/`。本功能允许用户在配置器中选择任意可写的本地磁盘文件夹，同时保持队列、会话、日志、数据库和配置仍位于项目内。默认行为不变；未主动修改时继续使用项目 `downloads/`。

目标包括：

- 在配置器中查看、输入和选择下载根目录，并可直接打开该目录。
- 保存后无需重启服务，尚未开始的任务和之后的新任务使用新目录。
- 已完成文件不迁移；已存在断点的任务继续从原目录续传。
- 支持跨磁盘保存，不进行完整文件的二次跨盘复制。
- 目标盘不可用或空间不足时保留任务并重试，不静默回退到旧目录。

不支持 UNC 网络共享路径，也不提供自动迁移已有视频的功能。

## 配置与界面

`AppConfig` 增加可选的绝对路径字段 `download_root`。字段缺失时解析为项目 `downloads/`，保证旧配置兼容。配置器的设置区域增加：

- 当前下载保存位置输入框。
- “选择文件夹”按钮，使用 Windows 文件夹选择器。
- “打开目录”按钮，打开当前已保存目录。
- 保存时的即时可写性和路径类型校验。

允许固定磁盘或可移动本地磁盘上的绝对目录；拒绝相对路径、UNC 路径、文件路径和无法创建或写入的目录。选择项目内目录时，不允许把 `.git`、`.venv`、`.runtime`、`.cache`、`.tmp` 或 `logs` 作为下载根目录。用户明确选择项目外目录是现有“项目数据留在项目内”规则的唯一例外，例外仅限视频成品和对应断点。

## 任务目录绑定

下载任务表增加可空的输出根目录字段。任务第一次实际开始下载时，把当时有效的下载根目录写入该字段；以后重试、续传和完成都使用已经绑定的目录。

因此：

- 已完成任务和文件保持原位置。
- 已经开始并生成断点的任务继续使用原目录。
- 尚未开始且未绑定目录的排队任务在领取时使用最新配置。
- 正在下载时修改配置，当前文件允许在原目录完成，下一项任务使用新配置。

旧数据库升级时不批量绑定所有排队任务。工作器领取旧任务后先检查现有项目 `.tmp` 中是否有该任务的合法旧式 `.part`；有则把任务绑定到旧的项目下载根，并把断点迁移到新的同盘隐藏临时目录；没有则绑定当前配置目录。迁移失败时保留原断点并报告可重试错误，不删除有效数据。

## 路径与断点布局

最终文件继续按“群组或频道 / 月份 / 文件名”组织。每个下载根目录下增加工具专用隐藏子目录：

```text
<download_root>/.tg-video-downloader/partial/
```

`.part` 位于该目录中，与最终文件处于同一卷。下载完成后先校验大小，再在目标卷内原子改名到最终路径，避免跨盘完整复制和双份空间占用。工具只会清理数据库明确关联的 `.part`，不得递归删除用户选择目录中的其他文件。

文件名净化、重复任务去重、512 KiB 对齐续传和完成记录语义保持不变。

## 运行时数据流

配置热更新向服务发布新的默认下载根目录。工作器领取任务时：

1. 读取任务已绑定目录；为空时绑定当前默认目录。
2. 验证目标目录可用，并在目标卷检查“剩余字节 + 512 MiB”空间。
3. 在专用隐藏目录创建或续传 `.part`。
4. 完成后原子移动到该任务绑定目录下的最终位置。

`open_downloads`、运行自检和状态错误使用当前配置目录；单个任务的磁盘检查使用任务绑定目录。目标盘移除、权限变化或空间不足时，任务进入现有重试机制并保留断点。

## 安全与错误处理

- 所有项目内控制路径继续经过 `ProjectPaths.assert_within_root`。
- 项目外路径由独立下载根验证器管理，不复用项目控制文件的路径断言。
- 任何删除、截断和原子改名必须先证明目标位于任务绑定目录的专用隐藏子目录或该任务的明确最终路径。
- 配置文件只保存用户选择的路径，不保存额外凭据。
- 无法访问目标盘时显示明确路径错误，不自动把文件写入其他位置。

## 测试与验收

- 旧配置缺少字段时仍使用项目 `downloads/`。
- 输入、本地磁盘、UNC、相对路径、文件路径和受保护项目目录校验。
- 保存后热更新，当前任务留在原目录，下一任务进入新目录。
- 未开始任务采用新目录，已有断点任务保持原目录。
- 旧式项目 `.tmp` 断点的安全迁移和失败保留。
- 不同磁盘下的空间检查、同卷原子完成和断点续传。
- 目标盘不可用时任务保留且不回退。
- 清理逻辑不能影响下载根中的无关用户文件。
- Windows 实机选择外部磁盘目录，完成一次真实续传并核对最终路径。
