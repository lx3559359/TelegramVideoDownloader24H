# 按检索结果选择视频下载设计

日期：2026-08-26

状态：待用户书面复核

目标版本：v0.3.0

## 目标

在保留现有自动监听、停机补抓和可选历史下载能力的前提下，新增一个轻量的手动视频检索入口。用户每次选择一个已经监听的群组或频道，按需从 Telegram 检索视频，在结果中逐条或批量勾选，再把确认项加入现有下载队列。

该功能只在用户主动点击“检索”时访问 Telegram，不建立长期全文索引，不增加后台扫描线程、常驻网络请求、状态轮询或独立下载器。

## 用户流程

1. 用户打开“视频检索”页。
2. 从当前配置中已经监听的群组或频道选择一个目标。
3. 可选填写关键词、开始日期和结束日期，并选择结果上限 20、50 或 100；默认 100。
4. 用户点击“检索”。界面异步发起一次 Telegram 请求并允许取消，不阻塞 Tk 主线程。
5. 界面显示符合现有下载政策的视频结果。用户通过空格或双击切换单项，也可以选择当前所有可加入结果或清除选择。
6. 用户点击“下载选中项”。新任务或允许重试的任务在一个本地事务中加入现有 SQLite 队列。
7. 如果后台正在运行，下载工作器在当前文件完成后按现有优先级领取任务；后台停止时，任务留在队列中等待下次启动。

## 范围

### 包含

- 每次检索一个已监听群组或频道。
- Telegram 服务端关键词检索。
- 可选的包含式开始日期和结束日期。
- 20、50、100 三档结果上限，默认 100。
- 普通视频以及 MIME 类型为 `video/*` 的普通文件。
- 逐条选择、选择当前可加入结果、清除选择和加入下载队列。
- 已完成、已在队列、可重新排队和可加入四类结果状态。
- 取消当前检索。
- 与现有保存目录、断点续传、去重、重试、状态心跳和单下载工作器兼容。

### 不包含

- 跨多个群组或频道的一次性检索。
- 常驻全文索引、后台目录扫描或定时检索。
- 缩略图、视频预览、在线播放或媒体解码。
- 保存检索词、检索历史、结果列表、说明文字或文件名到日志。
- 分页、无限滚动、自动加载更多或超过 100 条的单次结果。
- 自动下载全部检索结果。
- 改变现有自动监听和历史下载开关的语义。

## 界面设计

在“群组/频道”和“运行”之间新增“视频检索”页，继续使用 Tk/ttk，不引入 WebView 或新的 GUI 依赖。

页面顶部包含：

- 已监听目标下拉框。
- 可选关键词输入框。
- 可选开始日期和结束日期输入框，格式为 `YYYY-MM-DD`。
- 结果数量下拉框：20、50、100。
- “检索”和“取消检索”按钮。

结果使用 `ttk.Treeview` 文本表格，列为：

- 选择状态。
- 消息日期。
- 文件名或稳定回退名称。
- 文件大小。
- 视频时长；Telegram 未提供时显示 `-`。
- 简短说明；最多显示 120 个字符，仅保存在内存。
- 队列状态。

页面底部包含结果数、已选数、“选择当前结果”“清除选择”和“下载选中项”。“选择当前结果”只选择状态为“可加入”或“可重新排队”的项目。已完成以及已在等待、下载中或等待重试的项目不可重复选择。

检索开始后清空旧结果并禁用重复检索；取消后显示“已取消”且不展示部分结果。切换标签或隐藏到托盘不会自动发起请求。结果在 GUI 进程存活期间保留，新的检索、目标变化、退出账号或退出 GUI 时清空，永不写盘。

## 检索模型与网关

新增不可变的 `VideoSearchResult` 模型，包含：

- `message: MessageInfo`
- `duration_seconds: int | None`
- `caption: str`

结果身份始终是 `(chat_id, message_id)`。说明文字在规范化时去除换行并截断为 120 个字符；它只用于当前界面展示。

`TelethonGateway.search_videos(...)` 接受目标 ID、关键词、包含式 UTC 时间边界和结果上限。网关使用 Telegram 服务端的视频过滤与关键词搜索，随后调用现有消息规范化和可下载视频判定，继续排除 GIF/动画文档、圆形视频和非视频文件。

为了控制资源，即使过滤后结果不足，单次检索也最多读取 500 个候选消息；一旦收集到用户要求的 20、50 或 100 条即可停止。返回顺序为最新消息优先。

关键词为空时检索目标内最新视频。关键词的命中语义由 Telegram 服务端决定，通常覆盖消息正文、标题或说明文字；工具不承诺对未被 Telegram 建立索引的文件名执行本地全文匹配。

## 日期语义

界面日期按 Windows 当前本地时区解释：

- 开始日期表示当天 `00:00:00`，包含该时刻。
- 结束日期表示下一天 `00:00:00` 的排他上界，因此包含结束日期全天。
- 传给网关前转换为 UTC。
- 两个日期均可省略。
- 开始日期晚于结束日期时，在联网前拒绝检索。

网关尽可能通过 Telegram 参数缩小范围，同时对每个规范化结果再次执行本地时间边界判断，保证包含式日期语义不依赖服务端边界细节。

## 控制器与异步生命周期

`GuiController.search_videos(...)` 负责：

1. 验证凭据已保存且无活动登录任务。
2. 验证目标仍在当前白名单中。
3. 验证日期和结果上限。
4. 创建临时 `TelethonGateway`、连接并检查授权。
5. 收集网关异步结果。
6. 在 `finally` 中断开连接，包括成功、失败和取消路径。
7. 从本地状态库读取每项当前队列状态，返回给 GUI。

GUI 复用现有后台 asyncio 桥和短期 Future 轮询，只在检索执行期间每 100 毫秒检查 Future 是否结束。任何时刻最多存在一个检索 Future。开始新检索、退出账号或退出 GUI 前先取消旧检索并等待网关执行清理；不增加永久计时器。现有 2 秒心跳刷新保持不变。

## 队列语义

手动选中任务复用 `JobSource.LIVE` 及其实时优先级，避免修改 SQLite 的来源约束和执行数据库重建。语义如下：

- `completed`：显示“已完成”，跳过且不改变完成文件路径。
- `pending`、`downloading`、`retry_wait`：显示“已在队列”，跳过且不改变当前状态、优先级或下载目录。
- `permanent_error`：显示“可重新排队”；用户确认后改为 `pending`，清空下次重试时间和最近错误，重置尝试次数，同时保留已绑定输出根目录和合法断点。
- 不存在：以实时来源和优先级创建 `pending` 任务。

新增状态库批量接口，以一个 SQLite 事务处理所有选中项并返回 `added`、`requeued`、`already_queued` 和 `completed` 数量。数据库主键继续保证 `(chat_id, message_id)` 去重。手动任务不会抢占当前文件；单工作器只在当前任务结束后领取下一项。

未选择的检索结果不会写盘。只有用户点击“下载选中项”确认的消息，才按现有队列表结构保存下载所必需的消息 ID、日期、媒体类型、文件名和大小；这与自动监听任务的持久化范围一致。

关闭某目标的历史下载不会阻止手动选择的旧视频，因为手动任务使用非历史来源。移除白名单目标后，已经确认加入的任务遵循现有保留队列语义，但不能再从 GUI 对该目标发起新检索。

## 错误与隐私

- 未保存凭据、未登录、目标不在白名单、日期格式错误或无选择项：联网或写库前显示明确提示。
- 网络错误、Telegram 权限错误、FloodWait 和会话失效：通过现有异常映射显示脱敏消息。
- 消息在检索后被删除或失去访问权限：工作器沿用现有永久失败处理，不回退到其他文件。
- 取消检索：取消 Future，网关在 `finally` 中断开，不保留部分结果。
- 批量入队：本地事务要么完整提交，要么完整回滚；失败时不显示虚假的成功数量。
- 日志只记录检索阶段、目标的内部数值 ID、数量、耗时和错误类别；不记录群组名称、关键词、说明文字、文件名或消息正文。

## 性能边界

- 没有搜索时 CPU、内存、磁盘和网络开销为零，除页面已有控件占用。
- 每次最多一个 Telegram 检索连接、500 个候选消息和 100 个展示结果。
- 不下载缩略图，不探测媒体内容，不创建第二个下载线程。
- 结果对象在新检索或 GUI 退出时释放。
- 下载仍由现有单工作器串行执行，以保持长期后台运行时的低资源占用。

## 测试策略

### 单元测试

- 日期输入解析、包含式结束日期和 UTC 转换。
- 结果数量只接受 20、50、100。
- 说明文字规范化和 120 字符边界。
- 网关传递关键词和视频过滤参数。
- 最新优先顺序、可下载视频过滤、100 条结果和 500 候选上限。
- 控制器拒绝非白名单目标、活动登录、未授权会话和非法日期。
- 成功、异常和取消路径均断开临时网关。
- 状态库批量加入、重复任务跳过、完成任务保护和永久失败重新排队。
- GUI 表格渲染、空格/双击切换、选择当前可加入结果、清空和按钮状态。

### 集成与回归

- 使用伪 Telegram 客户端完成“检索—选择—入队—单工作器下载”的完整集成测试。
- 后台已有下载时加入手动任务，确认当前任务不被抢占且手动任务优先于历史任务。
- 修改下载位置后，手动新任务使用加入队列时尚未绑定、领取时解析的当前下载根目录；重排永久失败任务保留原绑定根目录。
- 运行项目完整 `scripts/check.ps1`，并保持现有全部测试通过。
- Windows 本地 900×720 界面验收：页面可见、列表不挤压运行进度、取消可响应、进度心跳继续刷新。
- 验收不发送 Telegram 消息，不删除真实会话、队列、断点或下载文件。

## 验收标准

- 用户可对一个已监听目标按关键词和可选日期检索最多 100 条视频。
- 用户可明确选择一个或多个结果并加入现有队列。
- 已完成和已在队列任务不会重复；永久失败任务可由用户重新排队。
- 检索和取消不冻结 GUI，不中断当前下载，不增加空闲后台活动。
- 自动监听、历史开关、下载目录、断点续传、托盘和在线更新行为保持兼容。
- 检索数据不写入配置、日志或新的长期索引。
